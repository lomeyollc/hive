# Focus — implementation plan

Spec: `docs/superpowers/specs/2026-09-25-focus-design.md` (binding authority — read it first).

## Global Constraints

- One active Focus per workspace, enforced by a partial unique index AND a clear error (REST 409, MCP error text).
- Task link is the label `focus:<focus_id>` only. Do NOT change BoardDO, task types or the DO SQLite schema.
- Workspace resolution for MCP tools copies `create_board` (src/worker/mcp/tools.ts): explicit `workspace_id` must be an active membership of `token.createdBy`; otherwise exactly one active membership, else error.
- REST routes are session-gated and check active membership of the Focus's workspace.
- Wire format is snake_case (match `src/frontend/lib/types.ts` conventions).
- Match existing code style: doc comments explaining *why*, like routes.ts and tools.ts.
- Icons: lucide-react only. UI components: existing shadcn components in `src/frontend/components/ui`.
- `npm run check`, `npm test`, `npm run build` must pass before each task's commit.

## Task 1: Backend — migration, focus module, REST, MCP, tests

Files:
- Create `migrations/0006_focus.sql` — tables `focuses`, `focus_metrics` and the partial unique index exactly as in the spec.
- Create `src/worker/focus/focus.ts` — the D1 functions listed in the spec (`getActiveFocus`, `listFocuses`, `startFocus`, `updateFocus`, `closeFocus`, `setMetric`, `focusProgress`) plus one `toWire` that returns the Focus with `metrics[]`, `progress {total, done}`, `days_left`, `overdue`, and `task_label` (`"focus:<id>"`).
  - id format `f-<8 lowercase hex>`.
  - `closeFocus` status must be one of `hit | missed | parked`; sets `closed_at`.
  - `setMetric` upserts by (focus_id, label); `current`/`target` optional on update, `target` required on create.
  - `focusProgress`: count non-archived `tasks_index` rows whose `labels` JSON contains `"focus:<id>"`, restricted to boards in the Focus's workspace; `done` = status `done`.
  - `ends_at` must be after `starts_at` (default `starts_at` = now).
- Edit `src/worker/api/routes.ts` — add the 4 REST routes from the spec to the dispatcher and the route doc comment. `GET /api/focus` takes `workspace_id` (required; must be active member). Returns `{ active, past }` (past = closed, newest first, limit 20).
- Edit `src/worker/mcp/tools.ts` — register `get_active_focus`, `start_focus`, `update_focus_metric`, `close_focus` per the spec. Extract the `create_board` workspace resolution into a shared helper and reuse it (create_board keeps identical behaviour and error texts). `get_active_focus` description must tell agents to label focus tasks with `task_label`.
- Update `/llms.txt` / docs source if MCP tools are listed there (grep for `create_board` in src/frontend/pages/DocsPage.tsx and any llms.txt source) — add the 4 tools.
- Tests `src/worker/focus/focus.test.ts` (vitest workers pool). D1 migrations are not applied in tests today: add the standard `readD1Migrations` + `applyD1Migrations` setup (vitest config binding + setup file) so tests run on real D1. Cover: start; second start in same workspace fails; start in another workspace succeeds; metric create then update; progress counts only labelled, non-archived tasks in the workspace; close sets status and frees the slot; overdue true when ends_at is past.

## Task 2: Frontend — banner, /focus page, task checkbox

Files:
- `src/frontend/lib/types.ts`, `src/frontend/lib/api.ts` — Focus types + client calls for the 4 REST routes.
- `src/frontend/components/focus/FocusBanner.tsx` — rendered in `AppShell` under the header on every protected page. Shows title, days left, metric bars (current/target), task progress (done/total), link to `/focus`. Hidden when no active Focus. When `overdue`: red styling and text "Past its end date — close or extend". Uses the current workspace from `workspace-context`.
- `src/frontend/pages/FocusPage.tsx` + route `/focus` in `App.tsx` + nav link "Focus" (lucide `Target`) in `AppShell` (desktop nav and the mobile menu, same as other links).
  - Empty state: explains a Focus in one line + "Start a Focus" dialog (title, why, NOT list one per line, end date, metrics label+target rows).
  - Active: edit dialog (title, why, NOT list, end date), metric current inline-editable, NOT list shown, "Close Focus" dialog (hit/missed/parked + lesson).
  - Past list: title, dates, result badge, lesson.
  - Use `use-document-title`.
- `CreateTaskDialog.tsx` and `EditTaskDialog.tsx` — when an active Focus exists, a "Part of current Focus" checkbox that adds/removes the `focus:<id>` label.
- Keep the banner query cheap: one `GET /api/focus` per workspace change, refetched after any focus mutation.
